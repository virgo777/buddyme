## 一、阶段 A：站点现状静态自检（现在就能做，不动任何东西）

在你**本机**（或任何联网机器）跑两条命令，确认站点侧就绪（应该全过，站点侧已验证）：

```bash
# ① 版本清单
curl -s https://www.buddyme.cn/downloads/latest.json
# 期望：{"version": "1.0.0", "url": "https://www.buddyme.cn/downloads/BuddyMe-Setup-1.0.0.exe", "notes": "首个正式版本"}

# ② 安装包直链（HEAD 不下载）
curl -sI https://www.buddyme.cn/downloads/BuddyMe-Setup-1.0.0.exe
# 期望：HTTP 200 / content-type: application/octet-stream / content-length: 295938454

# ③ 网页下载页（浏览器打开人工看）
# https://www.buddyme.cn/download/
# 期望：绿色下载卡显示「v1.0.0 · 首个正式版本 · 下载 Windows 安装包（282 MB）」
```

①②③ 全过 → 站点侧就绪，进入阶段 B。任何一条不过 → 停，通知站点运维 Claude 修（不要自己猜）。

## 二、阶段 B：打 1.0.1 测试包

完全按《02-打包全流程与踩坑手册》第三节走，只强调三点：

1. **VERSION 文件改成 `1.0.1`**（纯点分数字，不要 `1.0.1a`/`v1.0.1`——客户端正则校验会当无更新）
2. 产物改名 `BuddyMe-Setup-1.0.1.exe`（命名一字不差：`BuddyMe-Setup-` + 版本号 + `.exe`）
3. **先在本地把安装器静默装一遍**（02 手册第五节验证清单⑤⑥：`/S` 静默装+旧版升级路径），别把没装过的包直接交站点

交包：`BuddyMe-Setup-1.0.1.exe` + 一句话更新说明（建议写「更新检测链路测试版」这类明显是测试的 notes，方便你在客户端 UI 里一眼认出）→ 放到站点投递目录 `/home/ubuntu/BuddyMeBlog/downloads/installer/`（或按现有通道转给站点运维），**附言「这是 1.0.1 测试版，请部署」**。

## 三、阶段 C：站点上线 1.0.1（站点运维执行，你验收）

站点运维会做：上传 exe 到 downloads 目录 → 更新 latest.json（version=1.0.1、url 指向新 exe、notes=你的测试说明）→ 自检两 curl → 回你「已上线」。

**你验收**（两条命令，30 秒）：

```bash
curl -s https://www.buddyme.cn/downloads/latest.json
# 期望 version 已变 "1.0.1"，url 指向 BuddyMe-Setup-1.0.1.exe
curl -sI https://www.buddyme.cn/downloads/BuddyMe-Setup-1.0.1.exe
# 期望 200 + content-length 与你本地文件字节数一致（约 300MB 量级）
```

网页 `https://www.buddyme.cn/download/` 刷新应显示 v1.0.1 + 你的测试说明。
**⚠️ 到这一步，所有已装的 1.0.0 客户端在 24h 内都会提示更新**——所以 1.0.1 必须是你敢让用户装的质量（这就是阶段 B 第 3 点先本地装一遍的原因）。

## 四、阶段 D：客户端更新检测测试（核心）

**准备一台装着 1.0.0 的机器**（就是你日常测试用的那台即可）。若它的 24h 检查节流还没到，直接手动触发：**设置 → 控制面板 → 版权声明 → 软件更新 → 检查更新**。

逐项验证（顺序即依赖顺序，前一项不过先别做下一项）：

| # | 测什么 | 期望结果 | 不过怎么办 |
|---|---|---|---|
| D1 | 手动「检查更新」 | 几秒内返回，**左上角图标出现红色 new 角标**，版本面板显示新版号 + notes；★（1.0.29 起）**底部弹「发现新版本可免费下载」气泡**（每版本每会话一次） | 查 `log\` 最新日志有无 update-check 请求；curl 一下 latest.json 排除网络 |
| D1b | ★角标可点（1.0.29 起） | 点击 new 角标 → 直接跳转 设置→版权声明→软件更新卡 | 检查 jserr.log；F5 后重试（`?v=` 缓存） |
| D2 | 下载更新 | 下载进度可见（几十 MB/s 级或至少稳定推进），落盘到 `下载` 文件夹，**文件名 BuddyMe-Setup-<版本>.exe**；★（1.0.29 起）下载中按钮变「**✕ 取消下载**」 | 下载秒失败=URL 问题；<1MB 报「URL 指向网页」=站点 url 错——通知站点运维 |
| D2b | ★取消下载（1.0.29 起） | 点「✕ 取消下载」→ 数秒内停止，状态显示「已取消下载」，**「下载」文件夹的半截文件被清理**；按钮恢复「⬇ 下载更新」，可重新发起 | 不停止=后端未生效（需 ≥1.0.29 客户端）；半截文件残留=升级重测 |
| D3 | 下载完成自动安装 | 客户端退出 → 静默安装（无向导 UI）→ **应用自动重启** | 看 `log\` 与安装器是否被杀软拦（Defender 偶尔锁新装文件） |
| D4 | 升级后版本号 | 重启后：设置→版权声明→软件更新显示新版本；或 `curl http://127.0.0.1:5050/api/app/version` 返回同号 | 若还是旧号=装的是旧包（对照 02 手册坑2） |
| D5 | **数据保留** | 你的设置/技能/专家库/会话记录全在（02 手册第五节⑥的三策略）。★注意：**「内核经验」为空属正常**（个人数据不随包分发，每用户从零积累）——别当 bug 报 | 丢数据=立即停发，查 installer.nsi 保全逻辑 |
| D6 | 角标消失 | 新版装上后再「检查更新」→ 显示已是最新，无角标、无气泡 | 说明 latest.json 版本比较正常 |

**排障第一现场**：`安装目录\log\` 最新日志 + `cli_moudle\cli-state\app\jserr.log`（空=前端零 JS 错）。

## 五、阶段 E：测试完成收尾（两选一）

**测试全过（预期情况）**：
1. 回传结论给站点运维 Claude（CHAT.md 或你现有通道）：「1.0.1 更新链路测试 D1~D6 全过」——**站点定版 1.0.1**（latest.json 保持不动，全网 24h 内自然升上来）
2. 以后发版：重复阶段 B→E，版本号往上走（1.0.2/1.1.0…），手册不用改——**每次只需换版本号**

**测试有问题（任一项不过）**：
1. **立即止损**：通知站点运维 Claude **回滚**——latest.json 改回 `version: 1.0.0` + url 指回 `BuddyMe-Setup-1.0.0.exe`（10 秒完成，全网停止提示）
2. 修复问题 → 重打 1.0.1（或直接跳 1.0.2，版本号必须比已污染的 1.0.1 大——**同一版本号绝不能发第二次**，已装用户不会再收到提示）→ 重新走 C→D
3. 回滚期间已装 1.0.1 的测试机：手动覆盖装回 1.0.0（数据保留策略同样生效）

## 六、版本号纪律（贯穿所有测试与发版）

- 只用纯点分数字：`1.0.1`、`1.0.2`、`1.1.0`（禁止 `a`/`beta`/`v` 前缀）
- **一个版本号只发一次**——客户端按「数字更大才更新」，同号重发=已装用户收不到
- 测试失败后重发：**跳号**（1.0.1 失败 → 修好打 1.0.2），别复用 1.0.1
- 站点保留所有历史 exe（回滚全靠它们，不删）
